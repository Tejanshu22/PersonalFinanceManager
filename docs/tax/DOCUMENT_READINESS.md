## Period and form identity

Proposed metadata retains income-period start/end, printed period label, period kind (FY/AY or Tax Year), governing framework, source form/version, issue/download date, declared applicability, rule version and review state. Document issue/upload date never determines the income period. Missing/ambiguous values stay unknown. Tax Year naming does not mean all forms, rules or layouts are unchanged.

| Fictional period selection | Preserve/display | Behavior |
| --- | --- | --- |
| Income 1 April 2025–31 March 2026 | FY 2025–26 / AY 2026–27; earlier framework | A file uploaded in October 2026 keeps this period |
| Income 1 April 2026–31 March 2027 | Tax Year 2026–27; newer framework | As of this draft date the period is still running; distinguish partial-year coverage and annual evidence not yet issued |
| Prior-year loss/background document | Original period, plus relevance to selected-period package | Do not relabel it as a current-year file or count it as current coverage |
| Unknown, mixed or successor form | Printed form label and unresolved period/applicability | Manual tagging/storage if safe; no approved-assessment claim until reviewed |

**Open release dependency:** S06/S07 terminology differs, and S08 signals newer certificate labels. FIN-078 requires period handling, not universal successor-form extraction. FIN-079 remains Form 16 metadata extraction; no new Form 130/168 parser is added to V1 by this document. The reviewer must settle form mappings, supported checklist periods, transitional cases and whether any successor-format implementation needs separate approval. Unsupported/unapproved periods can store and organize safely but must show “readiness not assessed.” No automatic semantic equivalence between AIS, TIS, Form 26AS and Form 168 is assumed.

## Conditional document inventory

This is a **proposed preparation inventory**, not a compulsory list. Applicability starts from explicit user declarations and an approved period-specific rule set; the user may answer “unsure.” Do not infer tax regime, residential status, deduction entitlement or return eligibility from a statement. A CA decides which evidence is sufficient for the actual case.

All files require user confirmation of ownership, type and period. “Qualified review” below distinguishes (a) professional approval of the product checklist before publication, required for every row, and (b) case-specific professional interpretation where relevant. User confirmation is not professional approval. ## Checklist states and assessment rules

Recommend **status plus reasons**, not a 0–100 score (compatible with FIN-082's existing “score/status” criterion). No weighted tax-confidence metric, green filing-ready badge or percentage. Document completeness and tax correctness are different questions; professional sign-off on a checklist rule does not certify an individual return.

For each expected item record applicable/declared-not-applicable/unknown, reason and source rule; required issuer/account/coverage interval; received version; safe-upload state; identification/extraction confidence; user-review state; missing or awaiting-issuance explanation; related unresolved questions. Keep counts of documents distinct from counts of issues. Do not let one file representing a partial interval satisfy full-year coverage.

Deterministic proposed sequence (must be professionally reviewed and fixture-tested before implementation):

1. Pin owner declarations, period/framework, supported rule version and source/correction snapshot. If no approved matching rule exists, report **Not assessed — period/rules need review**. Do not compute a completeness denominator from guessed rules.
2. Build applicable expected items from that rule set and declarations. Unknown applicability stays visible; a user-declared exclusion with conflicting records becomes a question, not a satisfied item. Never turn blank answers into “not applicable.”
3. Match safe received document versions to type, issuer and interval; identify missing/partial/wrong-period/user-unreviewed items. “Awaiting issuance” is distinct from a document that should already be available. Redundant files do not improve status.
4. Separately list unclassified potential income, unreconciled imports, unresolved transactions, known reporting gaps, disputed values and complex sources. An unexplained credit does not become income just because it is positive.
5. Present all reasons: **Missing/awaiting documents**, **Owner review needed**, **Professional clarification needed**, and **Unsupported circumstances** may coexist. If applicable items are received/user-reviewed and supported coverage has no known gaps, display **Documents present for declared scope — professional tax review still required**. Unknown applicability, unresolved financial questions or material coverage gaps prevent this favorable overall message; item counts remain visible.
6. Any new declaration, file version or correction invalidates stale assessment and creates a new snapshot. Sharing may proceed for clarification with selected warnings; it must not suppress gaps or imply completion. Zero known applicable items with unanswered declarations is **Not assessed**, not complete.

Proposed copy: “3 of 4 expected document items received; one awaits issuance. Two transaction questions remain. This describes documents for your declared sources, not tax correctness.” Counts are not a legal assurance or a promise that all undisclosed accounts/income are covered. No automatic filing/return choice follows.
